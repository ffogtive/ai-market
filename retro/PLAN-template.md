# retro 템플릿 기획 v2 — 필터 뷰 + "어떻게 일했나" 분석

> 가설: 지금 페이지는 "무엇을 했나"(결과·결정)까지는 보여준다. 회고로서 가치를 올리려면 **"어떻게 일했나"**(프롬프트 습관·몰입·전환·위임·막힘)를 보여줘야 한다. 이 대부분은 LLM 없이 로그에서 계산 가능하고, LLM은 해석·코칭 몇 줄만 쓴다.
> 디자인은 와이어프레임 수준. 시각 디자인은 사용자가 나중에 입힌다.

## 0. 입력 데이터 (이미 있는 것)
이벤트 한 줄 = `source`(claude·codex·claude.ai·chatgpt·git·chrome·youtube), `ts`, `project`(작업 폴더/레포/사이트), `text`(프롬프트 최대 600자·커밋 제목·페이지 제목), `actor`(human=내가 입력 / agent=프로그램이 AI에 지시), `host`(기기).
새 수집 없이 아래 전부를 만든다.

## 1. 보기(필터)

| 보기 | 범위 | 비고 |
|---|---|---|
| 일간 · 전체 | 00:00–23:59 | 기본 |
| 일간 · 오전 | 00:00–11:59 | 새벽 에이전트 작업 포함 |
| 일간 · 오후 | 12:00–23:59 | |
| 주간 | 월–일 | 요일×시간대 히트맵 포함 |

- 한 페이지 안의 탭(전체/오전/오후)으로 전환. 숫자·분석은 구간별로 미리 계산해 넣고, LLM 요약은 하루 1번만 호출. "한 일"은 시각 필드로 구간에 나눠 보여줌. file://에서도 동작(JS 없이 CSS 탭, 또는 아주 작은 JS).
- 주간 페이지의 요일 칸 → 그날 일간 페이지, 일간의 오전/오후 탭 링크(`daily-DATE.html#am`).
- `retro app`에도 같은 필터(주간/일간/오전/오후) 제공.

## 4. 프롬프트 행태 지표 (LLM 없이 계산)
`human` 이면서 AI 도구(claude·codex·claude.ai·chatgpt)인 이벤트 = "내 지시".

| 지표 | 정의 | 왜 |
|---|---|---|
| 지시 유형 분포 | 규칙 기반 분류: **지시**(해줘/만들어/고쳐/추가/진행), **질문**(?, 어떻게/왜/뭐), **확인·승인**(응/ㅇㅇ/좋아/머지/계속, 20자 이하), **수정·불만**(아니/다시/왜 안/틀렸/말고), **붙여넣기**(터미널 프롬프트 `%`/`$`, Traceback/Error, 여러 줄 로그), **기타** | 내가 AI를 어떻게 쓰는지 |
| 길이 | 중앙값, 짧음(<20자)/보통/김(>200자) 비율 | 너무 짧은 지시 = 맥락 부족 신호 |
| 재시도·반복 | 30분 안 거의 같은 지시(앞 40자 유사) 반복 수, 연속 "수정·불만" 묶음 | 막힘 신호 |
| 붙여넣기 비율 | 붙여넣기 / 전체 | 수동 전달(에러·출력 복붙) 비중 → 자동화 후보 |
| 몰입 구간 | 활동(내 지시·커밋·탐색) 간격 < 15분으로 이어진 45분 이상 구간, 합계·최장 | 깊은 작업 시간 |
| 컨텍스트 전환 | 연속 이벤트의 프로젝트가 바뀐 횟수(웹 제외) | 산만함 |
| 동시 프로젝트 | 1시간 창 안 서로 다른 프로젝트 수의 최댓값 | 병렬 작업 |
| 레버리지 비율 | 에이전트 위임 수 / 내 지시 수 | AI에 얼마나 일을 맡기나 |
| 지시→커밋 | 프로젝트별 지시 수 대비 커밋 수, 첫 지시→첫 커밋 시간 | 대화가 결과로 이어졌나 |
| 반복 요청 Top | 정규화(숫자·경로 제거)한 지시 중 자주 나온 문장 | 규칙·스킬·자동화 후보 |
| 시간대 | 오전/오후/저녁/심야 지시 수, 첫·마지막 활동 | 리듬 |

주의: 분류는 휴리스틱이다. 페이지에 "자동 분류(추정)"라고 표시한다.

### 구현 메모 (`retro/analyze.py`, 상수는 파일 맨 위)
- 구간: 전체 0–24시, 오전 0–12시(11:59까지), 오후 12–24시(12:00부터). 시간대: 심야 0–6, 오전 6–12, 오후 12–18, 저녁 18–24.
- 분류 우선순위(먼저 맞는 것): 붙여넣기 → 수정·불만 → 확인·승인 → 질문(`?`로 끝남 / 영어 의문사로 시작) → 지시 → 질문(의문사·어미) → 기타. `[음성] `·`[첨부] ` 태그는 떼고 본다.
  - 붙여넣기: `user@host 폴더 %`, `user@host:~/dir$`, `$ git …` 같은 셸 프롬프트, Traceback, `XxxError:`/`Error:`/`npm ERR!`/`fatal:`, 로그 표지(시각 `12:00:01`, `[INFO]`, `file.py:12`) 3개 이상, 또는 줄바꿈 5개 이상. 수집 단계에서 공백·줄바꿈이 한 칸으로 합쳐지므로 줄 수보다 내용 신호에 기댄다.
  - 수정·불만: 아니·왜 안·틀렸·말고·안 돼·여전히 …, no/wrong/doesn't work. **"다시"는 혼자로는 불만이 아님** — 30자 이하(태그 제외)이거나 아니·왜·안 돼(안돼)·틀렸·말고·제대로와 함께 있을 때만. 그래서 "다시 해봐"·"아니 다시 제대로 해줘"는 수정·불만, "결제 페이지를 처음부터 다시 설계하고 테스트까지 추가해줘"는 지시.
  - 확인·승인: 20자 이하 + 승인 신호(응·ㅇㅇ·좋아·머지·계속·진행·ok·yes·lgtm…) + 작업 동사(만들·고쳐·추가·바꿔…, fix/add…) 없음 + `?`로 끝나지 않음. 그래서 "PR 머지해줘"·"진행해줘"는 승인, "좋아 그런데 버튼 색 바꿔줘"는 지시.
  - "해줄래?"·"can you …?" 같은 부탁형 질문은 지시.
- 길이: 짧음 < 20자, 김 > 200자(태그 제외 글자 수).
- 재시도: 30분 안에 **같은 도구·기기·프로젝트**의 앞선 지시와 거의 같음 = 영문자·숫자·한글만 남긴 앞 40자가 같거나 앞 80자의 difflib 유사도 ≥ 0.8(긴 붙여넣기에서 느려지지 않게 80자까지만). 확인·승인("계속" 반복)은 제외.
- 연속 수정·불만: 내 지시 순서로 2개 이상 연달아.
- 반복 요청 Top 5: URL·경로·파일명·숫자·문장부호를 지우고 소문자·공백 정리한 문장이 2번 이상. 확인·승인 제외. 예시는 처음 나온 원문 80자.
- 몰입: 내 지시·커밋·웹 방문(chrome) 간격 < 15분이면 이어지고, 첫–끝 ≥ 45분인 구간. 에이전트 이벤트는 활동이 아님. 구간 안에 내 지시나 커밋이 하나도 없으면(웹 방문만) 몰입이 아님 — 숫자·몰입 띠·LLM facts 모두 같은 구간을 씀.
- 작업 직전 탐색: 웹 방문 뒤 10분 안에 내 지시가 있으면 그 방문을 센다. 많이 본 사이트 Top 6.
- 컨텍스트 전환·동시 프로젝트·지시→커밋: 내 지시 + 커밋만(웹 제외), 프로젝트가 빈 이벤트는 건너뜀. 동시 프로젝트 창은 1시간. 첫 커밋 = 첫 지시 이후의 첫 커밋.
- 레버리지 = 에이전트 이벤트 수 / 내 지시 수(소수 둘째 자리, 지시 0이면 없음).
- LLM facts: 600자 이하. 넘치면 뒤 줄(반복 요청 → 지시→커밋 …)부터 뺀다.

## 5. LLM 추가 필드 (요약 스키마 확장, 호출 1번 유지)
- `keywords`(3), `til`(배운 것 1–3), `first_task_tomorrow`(1), `kpt`{keep, problem, try}
- `prompt_coaching`: {`good`: 원문 요약 + 이유, `improve`: 원문 요약 + 더 나은 문장 + 이유}
- `automation_ideas`: 반복 요청 Top을 입력으로 받아 1–3개 제안(규칙/스킬/스크립트)
- 입력에 §4 지표를 facts로 짧게 붙여 해석만 맡긴다. 지표를 LLM이 다시 세지 않게 한다.

### 리뷰 반영 (구현, 9/24) — 위 표와 다른 점
외부 리뷰를 받아 구현은 아래를 따른다(표보다 우선).
- **중립 이름·점수 없음:** 몰입 시간 → **연속 활동 구간**("기록이 이어진 구간입니다. 실제 집중·근무 시간과 다를 수 있습니다."), 컨텍스트 전환 → **기록상 프로젝트 변경**, 레버리지 → **내 지시 1건당 자동 실행 x건**(지시 0이면 "계산 불가", 주간은 주간 합계끼리 나눔). 가장 긴 구간·심야를 성과처럼 강조하지 않음, 좋고 나쁨을 뜻하는 색 없음.
- **관측 범위** 줄(일간·주간 맨 위): 소스·기기별 건수, 첫–마지막 기록, 꺼진 소스, "클라우드 Claude Code 대화는 수집하지 않음(커밋으로만 반영)". 주간 ▲▼는 퍼센트(지난주가 0이면 차이), 두 주의 관측 소스가 다르면 "관측 소스가 달라 비교가 부정확할 수 있음".
- 프롬프트 행태 → **프롬프트 문구 신호(자동 분류, 추정)**. 재시도는 같은 도구·기기·프로젝트끼리만. 반복 요청 → **유사 표현 후보**(원문 예시 2개, "비슷한 요청이 n회 있었습니다. 수정 과정인지 반복 업무인지 확인해보세요."). 코칭·자동화는 "검토할 후보", 코칭은 로그 원문을 인용할 때만 0~1개.
- LLM 정직성: 배운 것 → **학습 후보**. done·til·코칭에 근거(시각+도구) 배열, done에 `status`(완료/요청함): "요청은 완료 증거가 아니다". facts가 잘리면 "(일부 생략)".
- **가벼운 첫 화면:** 관측 범위 → 한 줄 요약/키워드 → 숫자 → 한 일 → 결정/막힘 → 내일 첫 할 일 → KPT. 학습 후보·흐름·문구 신호·AI 사용·탐색은 `<details>`(접힘). 커밋 없는 구간은 커밋 카드 숨김. 오전/오후 탭의 하루 단위 글은 "하루 전체 요약"으로 표시, 시각 없는 한 일은 전체 탭에만.
- 요약 새로 받기가 실패해 이전 요약을 보여줄 때: 만든 시각과 "현재 숫자와 다른 시점의 요약"을 요약 칸에 표시.
- AI 사용: `나 → Codex n건 → (자동 실행) Claude Code m건`, 자동 실행은 실행된 도구·기기별(누가 보냈는지는 기록에 없어 주장하지 않음).

## 8. 외부 리뷰 반영 (Codex/GPT, 9/24) — v2.1
> 가설: 리뷰의 핵심은 "기록된 활동을 능력·성과로 단정하지 말 것". 이름·설명·관측 범위·기본 화면만 바꿔도 오판 위험 대부분이 줄어든다.

**바로 반영 (템플릿 v2 에이전트에 전달)**
| 리뷰 지적 | 반영 |
|---|---|
| 활동을 능력으로 해석 | "몰입 시간"→**연속 활동 구간**("실제 집중 시간과 다를 수 있음" 설명), "컨텍스트 전환"→**기록상 프로젝트 변경**, 레버리지→**내 지시 1건당 자동 실행 x건**. 좋음·나쁨 색·점수 없음, 최장 구간·심야 강조 없음 |
| 관측 범위·누락 | 페이지 맨 위 **관측 범위** 줄(소스·기기별 건수, 첫–끝 시각, 꺼진 소스, "클라우드 대화는 커밋으로만 반영"). 지난주 비교 시 소스가 다르면 경고, 0이면 절대 차이 |
| 분류가 단정적 | "의도"가 아닌 **문구 신호(자동 분류, 추정)**. 재시도는 같은 소스·기기·프로젝트 30분 안만. 반복 요청은 **유사 표현 후보** + 원문 예시 2개 + "수정 과정인지 반복 업무인지 확인해보세요" |
| LLM이 확인 못 한 걸 단정 | "배운 것"→**학습 후보**. 한 일·학습·코칭에 근거(시각·소스) 필수, 빈 값 허용. "요청은 완료 증거가 아님" 규칙. 코칭은 근거 있을 때 최대 1개, "검토할 후보" |
| 섹션 과다 | 기본 순서: 관측 범위 → 한 줄 → 숫자 → 한 일 → 결정·막힘 → 내일 첫 할 일 → KPT. 흐름·프롬프트 신호·탐색·AI 사용 상세는 **펼쳐보기**. 커밋 없으면 커밋 카드 숨김 |
| 이전 요약 재사용 | 생성 시각 + "현재 숫자와 다른 시점의 요약" 표시 |
| 개인정보 설명 | "원본은 로컬, AI 요약을 켜면 선택된 기록(주간은 일간 요약도)이 본인 Anthropic 계정으로 전송", "수집 끄기는 기존 기록을 지우지 않음" |
